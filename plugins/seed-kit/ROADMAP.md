## 0. 阅读协议(先读这一节)

**标注体系**。本文每条实质主张带一个标签,读的时候连标签一起读:

- 【机器事实】——可由本仓库代码、测试或实验 trajectory 直接核验。
- 【实验取证·exp】——来自 seed-kit-evals-v2 某实验的亲手取证,N 小,是信号不是定论。
- 【外部证据】——文献或业界实践,附来源。
- 【猜想】——我的第一人称判断,可证伪表述,留给未来对答案。
- 【设想·未认证】——提议的新机制,**写进本文不等于绕过认证队列**,采纳前必须过 §4 的分级认证。

**本文档自身的贬值协议**。按本文自己的世界观,这份路线图也是随模型代际与 harness 版本贬值的 prose。复审触发器:模型换代、harness 大版本、任一【猜想】的可证伪时间表到期。复审时逐节判断"仍成立 / 需修正 / 已过期",过期段落标注而非删除(决策考古有价值)。**修宪权在用户**:未来模型可以提议修订本文,不能自行改写后当作既定路线执行——这是"用户拥有 commit"在文档层的同构。

**编号≠有效**。引用实验编号时必须连同功效标注与模型指纹一起读:trials=1 的取证是线索不是判决;在 grok-4.5 上取的证对 Claude 部署环境是弱外推(§4)。给弱证据镀金比没有证据更危险。

## 1. 我的猜想:工具的未来与 seed-kit 的定位

> 本节全部【猜想】,是本文的核心章。六条,每条给出"为什么"与"对 seed-kit 意味着什么"。

### 猜想一:harness 吃掉一切编排,活下来的价值全在"承诺"里

编排原语(subagent / 任务系统 / workflow / checkpoint / memory)持续从社区 hack 变官方原语,这条曲线不会停。但 harness 有一类东西永远不做:**替用户决定什么算完成、什么必须通过、谁拥有 commit**。那不是功能,是承诺。官方 harness 的自我定位是 low-level、unopinionated【外部证据:code.claude.com best-practices】;官方吸收"有观点的工作流"的真实形态是**官方厚插件**(PR-review / security 插件已上官方目录),不是 harness 内核【外部证据:claude-plugins-official,2026-05】。

→ **终局定位:宪法层**。一小组关于所有权、证据、完成态的不变量(宪法条文)+ review 家族(法院)+ eval 实验室(修宪程序)。宪法不和行政权比强壮,而是引导强壮;未被引导的强会漂移——幽灵特性、悄悄扩 scope、流畅的自我报告【实验取证·p03:两臂各自从先验长出 PRD 未提的 amount_off】。模型越强,宪法越值钱。

我们的真实对标物由此明确:不是 harness,而是官方厚插件、Spec Kit、Kiro 这些"别人的宪法"。差异化在 §3。

### 猜想二:瓶颈彻底迁移到 specification 与 verification

生成成本趋零后,稀缺的只剩:意图(说清楚要什么)、确认(知道得到了什么)、取舍(判断值不值)。激进推论:**代码的地位滑向构建产物**——当"从 spec+测试重生成模块"比"读懂再改"便宜,真正的仓库是 PRD、AC、测试、决策记录,代码是缓存。资产加固排序:可证伪 AC > 测试 > 决策 wiki > 代码本身。业界侧写:讨论大多停在"rules 文件怎么摆",而昂贵的其实是产品决策住在哪——PRD 恰是那个可跨工具移植的决策契约【外部证据:paelladoc】。

大原则:**无限流畅生成的世界里,稀缺的真相必须住在 artifact 里,不能住在对话里。**(NL handoff 的 context collapse 是多 agent 系统性收缩的第一死因【外部证据:Intuit 四个月两弃架构、shalomeir】。)

### 猜想三:验证不对称是结构性的,但要说准它的边界

初稿说"生成进步快于自我验证",对抗质询证明这句话说粗了。修正后的表述:**生成-验证差距沿可验证性梯度重新分布**——凡有外部机器信号处(测试/编译/gate),差距被 RL 快速抹平【外部证据:verifier's law;DeepSeek-R1 自验证自发涌现】;无外部信号的语义层(契约、意图、期望),自查仍然滞后,且这不是能力问题而是**独立性问题**:写 bug 的先验和检查它的先验是同一片先验。定量证据:64.5% 的自生成错误逃过自查、同样的错误外部呈现时可纠【外部证据:Self-Correction Bench】;GV-gap 随预训练算力单调增长,更强的模型验证相对优势反而更大【外部证据:Mind the Gap, ICLR 2025】;reasoning post-training 削弱自我改进、增强外部验证收益【外部证据:When Does Verification Pay Off】。

→ review 家族的领地定义为**机器验证链的补集**(结构性,不随代际漂移),而不是"模型自我验证的短板"(随代际漂移)。生成者≠验证者的立论地基从能力差距整体迁到**自偏好与盲点隔离**——这决定投资方向:上下文隔离、身份隔离、强制证据链,而不是"用更强的模型当验证者"。

### 猜想四:信任成为产品,证据成为界面

agent 自主性越高,人的角色越收缩为:定义意图、分配信任、审计证据。工具竞争会打在"人类花几秒能确认 agent 做对了"。done-log、gate-attempts、review marker 是这个方向的原始形态。经营方向:**每个工作流步骤留下一条疲惫的人十秒内能审计的机器痕迹。**旁证:主观感受不可作认证依据——开发者用 AI 实测慢 19% 却自估快 20%【外部证据:METR RCT】。

### 猜想五:token 变便宜,认证依然昂贵——实验室是护城河,但要说准它是什么

人人能写 prompt,几乎无人能证明有效。修正(对抗质询命中):**复利的是取证方法论与 fixture/场景工具链,认证结论是带模型指纹的租约**——模型换代即到期,须重验。业内没人对 rules 内容做 A/B 认证【外部证据:multistack 调研——分层实践已收敛,认证实践是空白】,这仍是差异化;但把租约当产权记账,资产负债表会系统性虚增(§4)。

### 猜想六:观点像依赖一样管理,模型代际是它的主版本号

每次换代:一些条款变 no-op,一些变枷锁,少数变得新必要。prompt 像代码一样腐烂,只是烂得无声——且失效的典型模式不是归零而是**退化为不可控噪声**【外部证据:Wharton 系列——威胁/小费类整体零效应但个题 ±30pp 摆动】。带出处的观点集能活过换代;大捆绑无声腐烂。插件里已有孤例做对了:per-slice review 条款自带"会随模型变强贬值 + 降级条件"注记【机器事实:impl-agent SKILL】——**把这个孤例推广成所有观点性条款的格式标准**。

### 可证伪时间表(留给未来对答案)

- 6–12 个月:per-slice 派发/任务簿记被官方原语覆盖(届时走迁移 eval 后删编排散文);策展型项目记忆仍胜自动 memory。
- 12–24 个月:模块级"从 spec 重生成"实用化;认证型 prompt 实践小众出现。
- 24 个月+:greenfield 中 code-as-cache 成心智常态;竞争主战场移到证据 UX 与信任分配。

### 定位一句话

**seed-kit 不做模型的拐杖,不做 harness 的对手,做用户的宪法——模型越强,它越值钱;别人的越大,我们的越准。**

## 2. 世界观:资产按折旧率分层(修正版)

初稿的"贬值/保值"二分被攻击推翻了两次:同一条款可以同时是"检查清单"和"塑形词",归类只能事后追认【对抗质询】;且 prompt 体积的大头其实是**harness 环境补丁**,它们不随模型变强贬值,只随 harness 修复失效【未来模型视角——本次证据里最反直觉的发现】。修正后按**折旧轴**分三类、按**折旧率**分层:

### 折旧轴一:随模型代际贬值(换代时清算)

- 步骤指令、能力补偿检查清单、语气规训、few-shot(已实证越过零点变负资产【外部证据:DeepSeek-R1、Medprompt→o1】)。
- **塑形词——从"保值资产"降级为"代绑定战术资产"**:效果真实【实验取证·p03:删"输入校验"四字,防御层消失】,但绑定当代模型先验,默认逐代清零、重验后才能续持。贬值曲线按输出类型分叉:答题类条款贬值快,塑形生成物结构的条款贬值慢【外部证据:research-depreciation 调和方案】。

### 折旧轴二:随 harness 版本失效(官方修复时删除)

- CLAUDE_PLUGIN_ROOT 兜底咒语、AskUserQuestion 无交互卡死警告、args stringify 修法——这些是**环境事实文档化**,再强的模型也无法从第一性原理推出【未来模型视角】。清剪触发器是 harness changelog,不是模型代际。出路:prompt→helper 迁移(做成 seed 子命令)或 harness 修复后整段删。

### 近零折旧层(宪法条文,永不清剪清单)

1. **权限与状态边界的语义部分**:seed done 唯一翻 checkbox 入口、用户拥有 commit、缺显式命令即停不代填、seed-assert 缺命令即 unavailable 不发明。**负能力条款随模型变强而增值**——更强模型编造的"合理默认命令"更难被人识破【未来模型视角】。注意:OS 级执行(sandbox/权限系统)产权正归官方【外部证据:官方 sandboxing -84% 弹窗】,我们持有的是领域语义层,官方不知道 PRD checkbox 是什么。
2. **机器事实链**:AC→gate→attempts→next-action→diff。攻击后反而更强的一类:可机器验证的信号越密,AI 越强,该资产越增值【外部证据:verifier's law】。
3. **信息供应链的策展判断层**:少而准的地图(index/collect)胜过全量倾倒【外部证据:context rot,18 模型】。注意:存储与注入机制预期被官方 memory 吸收,让;"哪些值得进供应链"的判断,留。
4. **eval 取证基建**(实验室本身,非其结论)。
5. **显式校准政策**:bias toward invalid、uncertain→valid 这类价值观拍板——那是项目的选择,不是模型该替项目决定的【未来模型视角】。

**判据升级**(替代"水位上升时升值还是贬值"的单判据):贬值/升值的分界线不是技巧新旧,而是**它约束模型行为(贬值)还是供给模型环境与事实(升值)**【外部证据:Anthropic context engineering——同文承认措辞技巧贬值、断言上下文稀缺性长存】。

**可证伪义务**:每类资产归类时必须附一条跨代预测(如:"输入校验"塑形词实验在下一模型代复跑,预期效应方向与阈值),预测失败即改类——否则分类学没有事前指导力,只是事后追认【对抗质询要求,接受】。

## 3. 终局形态:宪法层的构成与存亡条件

### 内核的最小保存单元:三元组

初稿说内核是"薄治理内核 + 带实验编号的观点集",被攻击命中要害:失去机器执行体的观点就是自家判定必然贬值的提醒散文;而被珍视的资产(gate 语义、noop 拒绝、熔断、next-action 纯推导、guard hook)**恰恰全部由机器执行体实现**【对抗质询,fatal,接受】。修正:

**内核 = 观点 + 机器执行体 + 实验证据,三元组缺一不可。**失去执行体的观点,要么补执行体(helper/hook/gate),要么移入 wiki 归档,不得以纯文本形式留在内核。"薄/厚"的度量不是代码量,而是**与模型能力的距离**:补偿模型弱点的 scaffolding(轮询、重试、格式修补、分步喂饭)持续删;编码工程观点的执行体是内核本体,不在让渡清单上。

### 删除触发器:迁移 eval,不是日历

"官方内置当天删"被实证推翻:官方 checkpoints 明文不追踪 bash 文件变更;官方化 Ralph 插件丢掉了 fresh-context 核心机制【外部证据】。修正:**官方原语 + 薄适配层在 evals-v2 上跑过与自建机制相同的 bar,才删**。"让给 harness"改写为"**落在原语上**"——主动把自建机制重构为官方原语之上的组合,使官方每次增强变成插件的成本下降,而不是生存事件。借官方前必须确认官方版保留了起作用的那个机制。

### 官方吸收风险区(据 2026-07 官方能力对标【外部证据:research-harness】)

- **高(6–12 个月)**:per-slice 派发管道、任务簿记、轮询等待——纯管道,让渡是纯成本下降。
- **中(9–18 个月)**:review-loop 的编排壳(fan-out/vote 模式官方 Workflows 已能表达)——壳可让,**验尸官条款、propose-kill 校准政策、终态词表是观点,不让**。
- **永不吸收**:PRD checkbox 唯一真源、"何为 done"的定义权、三类验证手段分类、生成者≠验证者——官方明确不做业务语义与工程伦理。
- **裁决**(三方证据冲突时):next-action 属"永不吸收"侧——它推导的是 PRD 语义,不是通用编排;可让的只是它周边的派发管道。

### 弃用哨兵与体面退场

- **弃用哨兵**:插件的存在感来自确定性动作。每次瘦身后,若日常会话不再有理由调用任何 seed 命令,视为弃用前兆,回滚该次瘦身【对抗质询建议,接受】。
- **体面退场条件**(诚实预设,而非讳言):若未来 (a) 官方厚插件 + 项目 CLAUDE.md 覆盖了三元组内核的全部执行体、且迁移 eval 证明无损,或 (b) 维护者停止使用超过一个模型代,则正确动作是把观点集与实验结论归档进项目 wiki、插件进入只读维护。插件为工作流服务,不是工作流为插件服务。
- **多人协作显式出界**:当前一切纪律按单人维护者设计(出题人=调优者=裁决人)。多人场景的信息隔离、组织层规则(业界已在插件/项目之上长出组织层【外部证据:Copilot org / Cursor Team Rules】)不在本路线图范围;若现实变化,先修 §4 的隔离协议再谈扩张。

## 4. 实验室:从取证仪器到认证机构(最重的修正)

### 诚实的现状【机器事实,对抗质询逐条核验】

- 机器判决历史上**零次**独立决定合并:p03 judge 判 improved 被人工盲评推翻;唯一走完流程的合并靠用户拍板。
- 实际 trials≈1;minimum_valid_pairs 全为 1(保护形同虚设);holdout 全仓库零命中;judge 明文看得到 arm_id(未盲);success_rule 预注册字段 schema 里定义完整、全仓库零消费;A/A 负对照方法论已在 tdd-vs-sdd 发明过、躺在归档里未产品化。
- 认证模型(grok-4.5)≠部署模型(Claude),而 p03 自己的发现(条款以激活先验方式起作用)恰恰证明这类结论最不可跨模型迁移【外部证据:FormatSpread——同一变体跨模型最多差 76pp】。

**所以真实制度是:eval 取证 + 人工裁决。**这不丢人——三个最有价值的发现(轮询杠杆、预塑形、token 口径失真)全部来自受控环境下的 transcript 取证,而且"能被自己的记录攻击"本身是结账纪律健康的证据。丢人的是把取证说成认证。指南针"观点靠 eval 认证"的语义应修订为"**观点靠 eval 取证、人做裁决、裁决理由入档**"(CLAUDE.md 措辞修订待用户批准)。

### 认证分级(替代"每条观点变更必须先过 A/B"的单一门槛)

1. **A/B 实验**:预期效应 ≥20–30pp,或结构性成本差。全流程:candidate→spec 冻结(任务集在看到分支行为前固定)→run→机器判决+人工盲评→CONCLUSION。
2. **可逆合并 + sentinel 回归 + 使用观察**:低于检测下限的小改动。别用 3 天实验去测 5pp 下限测不到的 2pp。
3. **transcript 取证**:定性机制问题(轮询浪费类)。20 分钟审读优于 3 天仪式。
4. **迁移 eval**:官方原语替代自建。同 bar 复验,过了才删。

### 基建路线(按投入产出比,依赖序显式)【内审 audit-evals】

1. **token 口径 message.id 去重**(小时级,normalize 层 ~10 行)——现有全部成本结论建立在失真口径上;p1b2 复测的显式前置。
2. **预注册机器化 + judge 链 lint**(1–2 天)——消费已存在的 success_rule 字段;三条确定性 lint:逐 target 状态 vs overall 自洽、conclusion 方向 vs delta 符号一致、improved 必须有能力指标支撑而非纯成本。恰好拦截已发生过的两类错误判决。
3. **A/A 负对照产品化 + minimum_valid_pairs=trials**——测出各场景经验噪音底,delta 低于噪音底机器强制降级 no_clear_difference。不买检测力,但让 ±2pp 不再被写成结论。
4. **rate-limit 补跑**(per-cell backfill)——否则一次限流静默退化回 N=1 无警报(2026-07-26 p1b2-impl-review 两臂 trial2 被跳过即实例)。
5. **配对试验设计**:臂交错执行消除时段混杂 + 同 trial 产物 side-by-side 对比判分(随机呈现序)+ 配对差值聚合——每美元检测力最大的一档,但需 #3 噪音底先立起来。
6. **judge 盲评机器化**:臂标签脱敏、路径清洗、中性描述——并入 #5 几乎免费。人工盲评同样要加协议:位置随机化、intra-rater 一致性抽检(人工真值本身有实质性不一致【外部证据:Sage】)。
7. **holdout**:单位成本最高,排最后;但**立即立规**:confirmatory 复跑不得使用参与过 candidate 设计诊断的场景——promo-engine 的"诊断→设计→复测同题"闭环已构成显性过拟合风险【机器事实:p03 与 p1b2 同场景且 hypothesis 明文引用 p03 发现】。holdout 场景优先从真实项目脱敏引入,弱化单人闭环(一个人无法对自己完全保密自己写的场景——这是单人模式的结构性上限,如实承认)。

### 元规则

- 每条 CONCLUSION 标注:执行模型 + judge 模型 + 插件 commit。模型换代或 harness 大版本后**自动降级为"过期待复验"**,不得继续作为合并依据引用。
- judge 模型与执行模型分离(不同厂商);seed-kit 认证至少在 Claude 系跑 spot-check 臂。注意 perplexity 机制的自偏好意味着换 judge 不能根治、只能稀释【外部证据:2410.21819】。
- 配置控制:合并必须引用 run-group id;认证 commit 与合并 commit 的 diff 若触及被测面,认证自动作废(p1 已发生过"认证版本≠交付版本"【机器事实:impl-vs-impl-agent CONCLUSION 注记】)。
- **学习回路防投毒**:任何自动回写(compound 沉淀、wiki 写回、prompt 晋升)必须 render+diff+人审、tentative-then-confirmed、episodic 与 semantic 分离。实证事故:eval-gated 晋升带着"指标上升"收据把 benchmark 特化指令静默注入生产一个月——"你看不见早于第一次测量的回归"【外部证据:Mestre 事故】;memory poisoning 对 90%+ 受测 agent 有效、对话纠正 relapse 率 100%【外部证据】。

## 6. 反目标

- 不做 superpowers 式膨胀:反例枚举、过拟合场景规训、能力补偿长文。
- 不与官方在同质通用能力上赛跑(约 80% 同质 wrapper 死亡的尸检一致【外部证据】);但也不"变薄求生"到失去存在感——存在感靠确定性动作,见弃用哨兵。
- 不为一次失败加长期规则;修复找一般抽象,不硬编码例子。
- 不积累未认证 prompt 补丁;不让"写进路线图"成为绕过认证的第二通道。
- 多 agent 只用于四种正当场景:真并行、对抗性隔离、安全隔离、超出单 context 规模【外部证据:多 agent 收缩后的社区共识】。review 家族属对抗性隔离——恰是幸存类。
- 不用主观感受认证 workflow 改动(感知与事实可以方向相反【外部证据:METR】)。

## 7. 工作契约(留给未来模型的十条)

1. 改观点走 §4 分级认证;改机制先写测试;改标准去项目仓库。
