# Init — 项目标准骨架初始化

> 调用名：`seed-kit:init`（全名见 conventions.md 登记表，别加 `seed-` 前缀）。

新项目初始化时，帮项目建立自己的标准骨架。**推荐而非强制**——插件给种子，项目采纳后拥有（标准在项目，插件不内置）。

## 先读码，再问人

落库的规则要可用，就得先拿准事实：

1. **读代码拿事实**：技术栈与版本、入口分布、目录结构、已有测试与质量命令、已有哪些标准文件（`CLAUDE.md` / `DESIGN.md` / `.claude/rules/`）。盘上能确认的不问用户；推荐项基于读码事实给，不凭空猜。
2. **访谈补盲区**（AskUserQuestion 一次一题、推荐项置首）——只问代码读不出的：
   - **演化方向**：项目下一步往哪长——会加什么、什么最可能被换掉。「新行为落在哪」表的前几行和门禁取舍都取决于它。
   - **在意的约束**：重复率 / 死代码 / 类型严格度 / lint，哪些在乎到要进机器门禁。
   - **栈内流派**：同一栈多种合理组织方式时（如 React 的状态与组件组织、游戏的 ECS vs OOP、CLI 的子命令架构），问项目选哪派——这是项目品味，插件不代选。

## 推荐骨架（三节，按项目情况取舍）

**1. 代码审查默认基准**：Fowler 12 味坏味道（《重构》ch.3）——项目未提供代码标准时，review 用它做默认基准：

- **Mysterious Name** — 名字看不出用途
- **Duplicated Code** — 重复逻辑
- **Feature Envy** — 方法伸手拿别的对象的数据
- **Data Clumps** — 同组字段老一起出现
- **Primitive Obsession** — 用基本类型代替领域概念
- **Repeated Switches** — 对同一类型反复 switch
- **Shotgun Surgery** — 一个改动散落多处
- **Divergent Change** — 一个文件为多个原因变
- **Speculative Generality** — 为不存在的需求加抽象
- **Message Chains** — 长串 a.b().c() 导航
- **Middle Man** — 纯转发
- **Refused Bequest** — 子类忽略大部分继承

三条绑定规则：项目文档化标准优先（repo 标准覆盖基线）；每条是判断不是硬违规；工具已强制的不重复报。

**2. 「新行为落在哪」表**：一节查表，每行"目标 → 落点"（如：加子命令 → `commands/` 注册；换供应商 → `providers/` 实现既有接口）。表的内容栈相关，按读码 + 访谈结果填真实落点；表的存在栈无关——每个项目都有"新行为落在哪"。实现与审查都从表定位，不临场判断；表上没有的新行为，先补表再动码。

**3. 机械门禁**：项目在乎且机器可查的约束（重复检测如 jscpd、死代码如 knip、lint、typecheck）接进项目质量命令——`seed done` 的 gate 会重放它们。判断留给审查基准，exit code 留给机器；只有判断没有机器判据的约束不硬凑门禁。

## 写入位置

用户确认采纳后，写入项目标准文件（看项目已有结构）：
- 有 `.claude/rules/` → 审查基准写 `code-review-baseline.md`，其余按主题分文件（如 `behavior-map.md`、`quality-gates.md`）
- 只有 `CLAUDE.md` → 分节追加
- 品味类内容（设计语言、参考产品）提示放 `DESIGN.md`

## 停止

用户确认采纳或明确拒绝后停止。不自动改文件——先推荐，等用户拍板。
