# Check — 题面对照 + 轻量快扫

> 调用名：`seed-kit:check`（全名见 conventions.md 登记表，别加 `seed-` 前缀）。

通用约定见 [`../references/conventions.md`](../references/conventions.md)。

收敛后的收尾自查。它抓一类 review 家族结构性看不见的失败：**声称在题面里、却没进 PRD**——review 只审"PRD 兑现了没有"，对照的是 PRD 自身，凡是收敛时被丢掉的声称对它天然不可见。防漏只能落在"收敛后对照题面"，本 skill 就是那一步。

## 何时

- impl / impl-agent 收尾时，编排者按本清单**内联执行**（不 dispatch 本 skill）——本文件是题面对照协议的 source of truth，收尾内联执行的就是这份清单。
- 用户单独触发：想用更干净视角（独立 agent 形态）重做对照，或在非 impl 上下文中做题面检查。

## 职责一：题面声称对照

1. **找到原始需求**：用户给出的原始需求输入（对话中的任务描述、需求文档、issue、题面文件）。**不是 prd.md**——PRD 是收敛结果，不能用收敛结果审收敛结果。原始需求在当前上下文不可得时，先向用户要。
2. **拆声称**：把题面拆成逐条声称——功能点、规则、约束、明示的例外路径。
3. **逐条问归属**："这条现在在哪？"合法归属只有两种：
   - 某条验收条目（指出 `S-NNN` 与具体 `* [ ]`）；
   - Out of Scope 中带（用户确认）标注的条目。
4. **无归属 = 缺口**。缺口不由你消化——按 brainstorm 的提问通道（一次一题、推荐项置首）交用户拍板：补进 AC（走 impl 补做），或经确认写进 Out of Scope（带（用户确认）标注）。**你单方判"不值得做"正是本 skill 要抓的第一目标，不要在自查里重犯。**

## 职责二：轻量质量快扫

- 项目 lint / type-check / test 存在则各跑一遍；看 `git diff` 快扫 debug log、死代码、机械小问题。
- 机械问题（lint nit、漏 import、死分支）直接修；判断性问题只报告，不悄悄重写。
- 不重复 review-loop 的五层深审——那是终态审查；本 skill 是收尾快扫，几分钟内完成。

## 职责三：准则对照

读项目质量标准（CLAUDE.md / DESIGN.md / .claude/rules/），对照本次 diff 触及的准则逐条检查改动是否遵守——每条给出 遵守/违反 结论，违反的列证据（file:line + 准则原文）。机械问题直接修；判断性问题（准则冲突、需改准则本身）报告用户拍板，不单方定。

## 双形态

- **内联（默认）**：主会话直接执行上述清单。代码由 seed-impl agent 写、对照由编排会话做，生成者≠验证者已成立。
- **Agent 形态（可选深审）**：用户要求更干净的视角时，派一个只读 subagent 执行同一份清单——把原始题面全文 + task 名 + 项目根传给它，回传归属表与缺口清单。

## 报告与停止

输出四段：声称归属表（声称 → S-NNN / OoS / 缺口）、缺口处置结果（用户拍板记录）、快扫结果（命令 + 修了什么 / 报告了什么）、准则对照结论（核对过的准则 + 遵守/违反 + 修了什么 / 报告了什么）。

全部缺口拍板处置后本 skill 结束：有补做的回 impl，无缺口则交还 impl 继续收尾（兑现对账；review-loop 是用户显式要求的增强项）。不自动推进其他阶段。
