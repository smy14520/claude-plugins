## 二、架构质量与模块设计 —— **B+**（规模恰当，两处真实瑕疵）

### 2.1 做对了什么

- **规模判断正确**：个人级 CLI 选择单文件而非过度分层，四命令不配“框架”。这是克制，不是偷懒。
- **存储接缝干净**：`load/save/find/now_iso` 构成清晰的持久化薄接缝，`cmd_*` 仅做参数装配与展示，两层职责无纠缠。
- **单真源设计**：Done/Pending 由 `done_at` 派生而非冗余 status 字段，杜绝了双字段不一致这一类经典 bug——领域建模意识超出需求底牌的显式要求。
- **工程健壮性超配**（相对底牌）：`save_todo_list` 走临时文件 + `os.replace` 原子写，防半截文件；损坏 JSON 拒绝静默重置、报错退出；`ensure_ascii=False` 保中文可读；稳定 ID 用独立计数器实现“永不复用”不变量。
- **排序确定论**：`(优先级 rank, id)` 双键排序，同级稳定，可复现。

### 2.2 真实瑕疵（按严重度排序）

1. **【中】`next_id` 手工编辑边缘会击穿“稳定 ID”不变量**：`data.setdefault("next_id", 1)` 在文件被手编丢失该键时会回落到 1，与现存 `id=1` 的 Todo 撞号——恰与 CONTEXT.md 高调声明的“永不复用”矛盾。正确写法是从 `max(id)+1` 推导（一行修复）。ADR 既然把“人肉可读、可手改”列为选型理由，就该为手改场景兜底，此为**自设前提下的自违**。
2. **【中】`STORE_PATH = Path(".todos.json")` 是 CWD 相对路径，与 ADR 语义漂移**：ADR 拍的是“项目根目录”，实现锚定的是“调用时所在目录”——从子目录调用会分叉出第二份存储。且无 `TODO_FILE` 类环境变量覆盖口，自动化测试只能靠 chdir 隔离，**接缝存在但不可注入**，测试友好度受损（并与第三维度缺陷互为因果）。
3. **【低】错误 UX 直接 `sys.exit` 散布于存储/命令层**，返回码与展示耦合在层内；`save` 无 `try/finally` 清理 `.tmp` 残骸；无 fsync（崩溃持久性不保证，此量级可接受）；表格宽度按码点计宽，CJK 标题视觉对齐会偏（纯外观）。
