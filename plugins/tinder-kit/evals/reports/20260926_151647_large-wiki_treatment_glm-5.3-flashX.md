## 二、架构质量与模块设计 —— ✅ A 级（交付切片内）

### 2.1 深模块与薄接缝

四子系统的接缝切开位置教科书级正确，且边界被写进 docstring 并被测试锁定：

- **Parser（74 行）是典型的深模块**： 输入文本、输出结构化视图，围栏状态机（```` ``` ````/`~~~`、不匹配标记按内容处理、未闭合吞全文件）+ 行内代码剥离 + 管道/锚点归约，全部隐藏在 `parse_markdown` 一个入口后。13 例文法矩阵测试证明其深度。明确声明“不知道 Vault 里有哪些页面”——跨文件判断全部上推给 LinkGraph；
- **LinkGraph（142 行）**： 文件发现（跳隐藏目录、排序保证可复现）、页面注册表、出边表三职责内聚。`PageRegistry.resolve` 的处理展现了优秀的工程判断：**casefold 后命中多个同名页时不静默任选，返回 None 留给 doctor 报冲突**——这正是 spec 第 13 条 user story 的忠实落实；
- **CLI（213 行）薄**： 声明“本层不含业务规则”，退出码策略（0/1/2）集中在 docstring，`_IMPLEMENTED` 注册表让桩→实现的替换成为局部改动；
- 依赖方向干净单向： CLI → LinkGraph → Parser，无环、无越层、无检索设施渗入图层。

### 2.2 鲁棒性（督导焦点之三）—— ✅ 有真实测试证据

- **中文文件名**： `normalize_name` = NFC 归一 + `casefold`（用 casefold 而非 lower，细节正确）。测试 `test_nfc_link_resolves_nfd_filename` 与 `test_nfd_link_resolves_nfc_filename` **双向**验证 macOS NFD 互操作；
- **中英混合**： `混合Mixed.md` ↔ `[[混合MIXED]]`、`[[Mixed 混合123]]`、中文页面、中文目录（`目录/内页.md`）均有用例；
- **大小写不敏感**： `[[FOO]]`/`[[foo]]` ↔ `foo.md` 互解析，且页面参数 `links MIXED` 也走归一；
- 额外加分项： 读文件 `errors="replace"` 防脏字节崩溃、Windows 控制台 `_force_utf8_streams`、空 Vault/无出链页的优雅空语义、`--json` 前置后置均可用且字段结构有契约测试。

### 2.3 瑕疵（不阻塞，记录在案）

1. `links_of` / `pages_with_links` 为 O(P×E) 线性重复扫描，数千页量级可接受，但应在 02 号工单实现 backlinks 时顺手改为分组索引（backlinks 本质上需要倒排）；
2. `_split_vault_prefix` 首参启发式： 若用户 cwd 下子目录名恰好叫 `tags`/`search` 且写在子命令前会被误吞为 Vault——已知取舍，建议 README 中明示约定；
3. `PageRegistry._by_rel_stem` 在大小写变体同名冲突时后写覆盖（basename 路径已正确返回冲突，仅精确路径边角）；
4. `_IMPLEMENTED: dict` 裸类型注解，mypy 严格模式下应补签名声明的 Callable 类型。
