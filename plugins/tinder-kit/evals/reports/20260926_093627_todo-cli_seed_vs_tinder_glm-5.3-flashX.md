## 三、架构质量与模块设计

```
cli.py    argparse 解析 · 渲染 · 退出码映射 —— 不懂领域规则
core.py   记录语义 · 生命周期 · 过滤排序 —— 纯内存函数，只抛 TodoError，永不触盘
```

- **store 是深模块正面样本**：对外仅 `load/save` 两个动词，内部封装 schema 校验、单调计数、原子写、失败清理、错误语义五大职责；
- **core 为纯函数集合**，使 CLI 退化为“解析器+渲染器”，正中场景考察点；
- **防呆细节密度高**：`allocate_id = max(next_id, max(id)+1)` 防手改文件 id 复用且有专项单测；validate 对未知字段宽容、对依赖字段严格；done/completed_at 一致性不变式下沉到存储校验层；空 clear 提示走 stderr 且磁盘字节不动；

## 二、架构质量与模块设计

### 2.1 接缝结构（深模块 × 薄接缝的正面案例）

```
cli.py（薄翻译层）──构造注入──▶ TodoApp（行为接缝）──▶ TodoStore（持久化接缝）──▶ models.py（词汇叶节点）
  argv → 领域调用翻译              add/list/done/rm          load/save + 校验 + 原子写
  仅捕领域异常，exit code 归一      TodoNotFoundError          TodoStoreError（归一损坏）
```

- **TodoStore 是典型深模块**：接口面积极小（`load`/`save` + 一个错误类型），却隐藏了五件事——路径解析（`TODO_HOME` 环境覆盖 = 天然测试注入点）、缺文件语义（视作空库）、schema 逐项校验、五类结构损坏归一为单一 `TodoStoreError`、`tmp + os.replace` 原子替换。接口简单、行为复杂，正是 Ousterhout 定义的好模块；
- **cli.py 足够薄**：纯 argv 翻译，业务判断为零；`main(argv, store_path)` 双注入参数让 CLI 层测试无需 monkeypatch 主目录；
- **组合根清晰**：`TodoStore` 由 CLI 组装后注入 `TodoApp`，依赖方向严格单向（models ← store ← app ← cli），无循环依赖；
- **单一序列化形状**：`todos_payload` 同时服务存储文件与 `--json` 输出，消除了“两套序列化”的经典漂移源——这是 Turn-3 双轴自审自己收敛出来的，说明审查是真审查。

### 2.2 缺陷与瑕疵（静态审计发现，均非阻断）

| 级别 | 发现 |
| :--- | :--- |
| Nit | `models.py` 顶部 `import json` 未被使用——双轴 standards 审查漏网之鱼，lint 可拦 |
| Nit | `Todo.from_dict` 用 `int()` 强转 id：`true`→1、`1.7`→1 会被静默接受，属“可强转的结构损坏未拦截” |
| Nit | 重复标签 `-t a -t a` 原样入库不去重，CONTEXT.md 亦未规定去重口径（对照并行 run 曾明确“自动去重”，本 run 存在口径欠账） |
| Nit | `rm` 成功时零输出、`list` 空结果零输出，极简风格可辩护，但缺一行确认略损 CLI 反馈感 |
| 记录在案 | 多进程并发为 last-write-wins——ADR Consequences 已声明“未来规模/并发需求须另立 ADR”，算**已声明的边界**而非隐瞒 |

**维度小评：95/100。分层、信息隐藏、依赖注入、异常归一均为高水准；瑕疵集中于边角口径未成文。**
