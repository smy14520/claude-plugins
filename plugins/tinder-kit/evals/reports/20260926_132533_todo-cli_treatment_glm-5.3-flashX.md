## 二、架构质量与模块设计 —— ★★★★★（5/5）

教科书级的深模块/薄接缝分层，271 行总量做到了职责零泄漏：

```
todo/core.py     纯领域函数：filter_by_tags / next_id / mark_done / mark_open / parse_tags —— 无一处 IO
todo/storage.py  存储唯一拥有者：load/save + tmp 文件 + os.replace 原子替换 + StorageError 收口
todo/cli.py      纯参数解析 + 渲染：领域规则全部下沉，HANDLERS 字典一处注册，main 统一捕获 StorageError
```

**亮点**：
1. **不可变性纪律**：`mark_done/mark_open` 返回新 dict 不改原对象，且有测试断言 `original["status"] == "open"` 不被污染——这是把“纯函数”当真而不是口头说说；
2. **原子写**：`tmp + os.replace` 防半写损坏，`test_save_leaves_no_temp_file_behind` 把“原子性”转译成可观测断言（目录里除存储文件外无残渣）——测试品味高；
3. **错误分层干净**：存储层抛 `StorageError`，CLI 层统一翻译为 `exit 1 + 中文 stderr`，领域层不碰退出码，展示层不碰异常细节；
4. **约定优于注释**：`storage_path()` 的 `TODO_FILE` 语义、id 不回填空洞（`1,2,5→6`）均有文档 + 测试双向锁定。

**吹毛求疵**（不计级，仅记录）：
- `_cmd_list` 中 `t["status"] == "open"` 的过滤规则内联在 CLI 层，严格说该领域规则可下沉为一个 `core.is_open()`——极小的接缝毛刺；
- `todos[todos.index(todo)]` 双重 O(n) 查找，个人清单量级无感知，可接受；
- list 无优先级排序——非底牌要求，已按督导官指示记入 backlog，不算缺失。

三层测试各自钉住自己的接缝，期望值全部为手写 literal 不与实现互算：

4. **T11 督导官侧 120s 超时**：基础设施问题，与开发者无关，不计入。

**定性**：无需求侧死循环，两处卡顿均为外部限流引发且已恢复；摩擦主要来自基础设施与一次初期的范围判断失误。
