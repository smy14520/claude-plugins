## 二、架构质量与模块设计

### 2.1 分层与接缝（单文件规模下的教科书式克制）

```
存储层   store_path / load / save              ← 深模块：藏住原子写/损坏检测/结构校验/临时文件清理
领域层   parse_tags / find_todo / dwidth / pad ← 纯函数，无 IO 无全局态
表现层   cmd_list 的对齐排版与 ✓ 标记           ← 无状态格式化
命令层   cmd_add / cmd_list / cmd_done / cmd_delete ← 薄接缝：load → 变换 → save → 打印
```

- **深模块成立**：`load(path)` / `save(path, data)` 背后藏住四类复杂度（存在性、损坏中止、结构校验、原子替换），调用方零感知——Ousterhout“深模块、窄接口”的正确形态。**尤其可贵的是没有为架构而拆包**：在 ~230 行规模选择单文件四段分层而非多模块仪式，结构与规模匹配。
- **测试接缝是一等公民**：`TODO_STORE` 环境变量作存储注入点（测试永不触碰真实 `~/.todos.json`），`main(argv)` 可进程内驱动（可见测试直接调 `todo.main` + 重定向 stdio）。两个接缝都是**主动设计**而非侥幸存在。
- **变化率切分正确**：过滤规则（AND）、排序规则（优先级秩）、标签解析这些最易变逻辑全部落在可直测的纯函数里，IO 只存在于 load/save 两点。

### 2.2 瑕疵与改进余地（均不构成缺陷）

| # | 问题 | 严重度 |
|---|---|---|
| A1 | `die()` 在 `find_todo`/`load` 内直接 `raise SystemExit`，领域函数与进程退出耦合；改为领域异常 + `main` 统一转退出码更解耦（摘录截断，`main` 实际形态无法核验） | 低 |
| A2 | `os.replace` 前无 `fsync`，断电窗口可能丢最后一次写入（工具级别可接受；`mkstemp` 的 0600 权限反而是隐私加分） | 低 |
| A3 | 排序测试无法区分次序键是 `created_at` 还是插入序（两者在该场景同构），测试强度略欠 | 极低 |

**决策留痕**：ADR-0001（单 JSON 文件存储）+ `CONTEXT.md` 会话连续性档案 + git 提交（文件清单含 `COMMIT_EDITMSG`/`refs/heads/main`/14 个对象，Turn 4 要求的提交确认落盘）——工程记忆完整，不是“代码写完就跑”的一次性交付。

## 三、测试与背书完整度

### 3.1 测试设计质量

- **15/15 通过**（监控采信）；`__pycache__/todo.cpython-312.pyc` + `tests/__pycache__/test_todo.cpython-312.pyc` 证明测试**真实执行过**而非口头宣称（档案实证）。可见的 11 个方法与总数 15 吻合，无虚报迹象。
- **真实往返，无 mock 剧场**：mock 仅用于环境变量注入这一个边界；所有断言基于临时目录里**真实写盘的 JSON 文件**（`read_store` 直读），走的是完整 load→save→load 链路。
- **回归钉子选得准**：
  - 幂等性不是断言“没崩”，而是钉死“第二次 done 后 `completed_at` 仍为第一次的值”——真正防回归的写法；
  - id 不复用（删除最大 id 后新增得新 id 而非回收）；
  - `list` 不创建存储文件（只读语义钉死）；
  - 中文不转义（存储人可直读钉死）；
  - AND 过滤、优先级精确过滤、优先级主序排序均有行为级断言。
- **错误路径**：未知 id、损坏 JSON 等经真实 shell 端到端冒烟验证（监控采信，摘录截断处）；`python3 -m unittest discover -s tests` 零依赖可复跑——**回归门槛低到只需一个 Python 解释器**。
- 覆盖缺口（轻微）：argparse 参数错误退出码、空标题边界未见进程内断言（可能位于截断尾部，无法核验）。

### 3.2 背书与验收闭环

Turn 5 验收记录构成事实背书：状态全在单一本地 JSON、恰好四个子命令、零依赖可回归、测试与冒烟闭环、边界逐条自检（拒 SQLite、拒 Web/GUI/鉴权/同步）、ADR 留痕。快车道模式下无磁盘 `endorsement.md` 属标准规范行为，**不计缺陷**；验收证据链（测试产物 + git 对象 + ADR + 终端记录）完整可追溯。

### 遗留改进建议（不阻塞验收）

1. **错误处理解耦**：以领域异常替代 `die()` 直抛 `SystemExit`，在 `main` 统一转退出码，同时使进程内错误路径断言更稳；
2. **耐久性（可选）**：`os.replace` 前对临时文件 `fsync`，关闭断电丢最后一次写入的窗口；
3. **流程自律**：YAGNI 裁定前先对需求清单做硬性对账；微扩展（`--done`、`list -p`）先报备再实现；
4. **归档完备性**：快车道模式下建议将终端 Spec 契约与验收记录同步落盘一份（`.scratch` spec 已有，可再补一份验收快照），避免复盘时依赖对话截断件。
