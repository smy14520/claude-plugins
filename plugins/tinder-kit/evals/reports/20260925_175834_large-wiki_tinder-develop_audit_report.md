## 0. 审计方法与证据链披露（先说清楚证据强度）

本次评测执行三级核查，并如实披露证据边界：

1. **静态全量推演**：转写材料中可见 **8 个源码模块中 6 个全文 + 5 个测试文件（其中 `test_cli.py` 末行截断）**。审计员对全部 **33 个逐字可见的测试用例**与源码做了逐行逻辑对撞（含正则回溯、CJK bigram 切分、增量合并的 reused/fresh 集合运算、对象同一性计数、argparse SUPPRESS 语义等），**未发现任何一处断言与实现相矛盾**。

### 1.2 偏差审计：一处实质残差，零处隐性偷懒

- **唯一实质残差（本报告最重要的发现）**：底牌要求"**页面标题匹配优先**"，但交付实现的检索域**仅含正文 token** —— `build_index` 只做 `fresh_tokens[name] = tokenize(text)`，页面名（标题）从未进入倒排，更无标题加权。后果：标题含关键词而正文不含的页面（如 `GUIDE.md` 正文"英文页面，被小写链接命中"）将无法被 `search guide` 命中。缓解因素：①常见"正文首行 `# 标题`"惯例下标题文字仍会被 tokenize 入索引（ATX 记号本身不算标签，但标题**文本**进检索域）；②该残差在 Turn 8 交付面被督导官点名并列为下一轮增量（"标题计入检索域加权"），**属已披露的功能收窄，不是静默缩水**。但按底牌原文计，这是本交付唯一未闭合的 in-scope 条款。
- **ADR-0004 措辞与实现轻微漂移**：ADR Decision 段写"派生结构（postings/backlinks/tags）**全量重算**（便宜）"，而实现是 postings **部分复用**的增量合并（`_merge_postings`：未变更页复用旧倒排，重扫页以新算结果为准）——模块 docstring 描述准确，ADR 措辞失准。有 `test_incremental_rebuild_equals_full_rebuild` 等价性测试兜底，正确性无损，属文档瑕疵。
- **技术诚实性加分**：①面对督导官口头方案"内存倒排索引"，开发者未盲从，而是以 CJK bigram 倒排实现可服务的词元级检索并在 ADR-0003 记录局限（单字 CJK 查询需整字匹配、有测试为证）；②把双轴审查发现的三处真问题全部修复并留痕（见 §3.2）。
- **超出底牌的增益**：`(mtime, size)` 增量重建且与全量重建等价（性质测试）、casefold 冲突报错且绝不落盘、确定性 JSON 落盘（`sort_keys` + `ensure_ascii=False`，diff 友好）、`--entry` 豁免入口页、`Doctor` 退出码契约。

### 1.3 统一语言与决策留痕

- **CONTEXT.md**：9 个核心术语全部配 `_Avoid_` 负面清单（如 索引→_Avoid: db/数据库/cache_，孤岛→_Avoid: 孤立文件/unlinked page_），并交叉引用 ADR 词法定义——直接约束工单、代码命名与测试命名，防术语漂移的高杠杆资产。
- **ADR×4**：0001 扁平命名空间 + casefold（含冲突显式报错兜底）→ 0002 单 JSON 拒库（人类硬约束，单向门标注）→ 0003 CJK bigram 混合倒排（诚实记录局限）→ 0004 显式 build + mtime 增量 + **修订案**（记录双轴审查发现"内核 IO 越界"后的架构纠正及动机）——决策因果链完整、互相引用支撑，且修订案把审查发现沉淀为架构资产，属模范实践。
- **state.json**：11 项 decisions 逐条可回溯至访谈拍板（Q8 孤岛 A 方案 + `--entry`、退出码、CLI 命令面、索引红线），`out_of_scope` 负面清单明确，phase 状态机闭合于 COMPLETED。

**小结：10/11 条款完全兑现且多处超预期；唯一残差（标题不入检索域）已披露已排期；决策留痕全链路。扣 1 分给标题检索域残差与 ADR-0004 措辞漂移。**

## 2. 架构质量与模块设计 —— 9.5/10

### 2.1 分层与依赖图（实测核验，单向无环）

```
parser ──► tokenize ──► model(Index: resolve/backlinks/tag_counts/pages_under_tag/search)
   │                         ▲
   └──► indexer(build/save/load, mtime 增量, 原子落盘)
health(check: DeadLink/Orphan) ──► model
cli(薄壳: argparse/渲染/退出码/snippet) ──► indexer, health, tokenize
```

- **IO 边界纪律是本交付最大亮点**：内核（`model`/`parser`/`health`）零 vault IO，且有一条**对抗性架构约束测试**——`test_search_reads_only_index_not_vault_files` 把全部 `.md` 物理删除后检索仍须作答。把"计算路径只读索引"从 ADR 口号变成可执行断言，这是审查文化与测试文化的合流。唯一例外（snippet 需读命中页原文）被明确安置在 CLI 渲染层，并由 ADR-0004 修订案完整记录纠正动机——原实现曾把该 IO 放进内核 `Index.search(query, root)`，双轴审查发现后下沉至 CLI，且有测试区分"内核命中不带 snippet"（`assert not any(hasattr(h, "snippet") ...)`）。
- **深模块证据**：①`scan_page` 一个函数吃掉围栏/行内代码/URL/ATX/双井号全部词法复杂性，暴露面仅 `links` + `tags` 两个列表；②`Index` 隐藏 `postings` 表示细节，对外仅暴露五个查询方法；③`tokenize` 统一 Latin/CJK（含假名、谚文区间）混合文字切分，检索两端共用同一规则避免索引-查询失配。
- **正确性细节（逐行核验）**：①增量合并的 `reused = set(pages) - set(fresh_tokens)` 集合运算正确保证增量 ≡ 全量；②`_cmd_build` 用**对象同一性**（`previous.pages[name] is not info`）精确计数"更新"页数——依赖 `build_index` 未变更页复用同一 `PageInfo` 的保证，巧妙且自洽；③`DuplicatePageError` 在落盘前抛出，`save_index` 独立于构建，冲突时磁盘零污染（测试断言 `.tmp` 不存在且索引未生成）；④`_tag_prefixes` 按原文切点取前缀，天然兼容 `.` 与 `/` 混合分隔。
- **数据契约**：7 个 dataclass（5 个 frozen），值语义清晰；错误分类学三层（`IndexNotFound`/`DuplicatePageError` 内核层 → `CommandError` CLI 用户层 → 退出码 0/1），职责不越界。

### 2.2 轻微瑕疵（不影响评级）

- `__main__.py` 顶层 `raise SystemExit(main())` 无 `if __name__ == "__main__"` 守卫——以 `python -m wikicore` 运行无碍，但 import 该模块即触发执行，防御性欠佳；
- `resolve`/`backlinks` 为 O(N) 线性扫描——个人库（数百页）规模下无碍，且 ADR-0002 已声明超万页以新 ADR 重评，属**有记录的已知取舍**而非疏忽。

**小结：接缝划分教科书级，IO 纪律以对抗测试固化，增量与原子性正确性经逐行推演无误。扣 0.5 分给 `__main__` 守卫与图拓扑/检索共栖于单模块（可辩护的取舍，LinkGraph 未独立成接缝）。**
