# 全量扫描 + 内存索引，禁用数据库

个人 Vault 量级（数千文件）下，每次命令全量扫描 + 内存构建索引是毫秒到秒级，换来零状态、零缓存失效、零运维。用户钉死红线：**绝不引入 SQLite / 向量库 / 外部检索服务**；索引只允许存内存，未来若确需持久化，上限是单个 `.wiki_index.json` 文件，不得演进为数据库。

## Consequences

- 无缓存层：每次运行重新解析全部页面（这是接受的代价，见量级假设）
- `.wiki_index.json` 是未来唯一许可的持久化形态，仅为性能演进的预留边界，v1 不实现

## Revisit When

- Vault 文件数到达数万且扫描延迟明显可感
- 出现常驻服务/即时响应场景
