# Spec: wiki-cli — 个人本地 Markdown 知识库的结构洞察工具

> 对齐依据：`.forge/wiki-cli/state.json`（方案确认包，人类已确认）。术语遵循 `.forge/CONTEXT.md`，存储决策遵循 ADR-0001。

## Problem Statement

个人的知识以一堆散落的 Markdown 文件存在，`[[链接]]` 与 `#标签` 织成的知识网络是隐形的：不知道某页面被谁引用、某标签覆盖了哪些页面、哪些链接早已失效、哪些页面成了无人引用的孤岛。人需要一个零外部依赖、纯本地、随敲随用的工具来让这张网络可见。

## Solution

wiki-cli：一个对知识库（vault）严格只读的 Python CLI。在笔记目录里直接敲命令（或 `--vault` 指定路径），通过五个子命令做结构查询与体检：`links`（正向链接）、`backlinks`（反向引用）、`tags`（标签聚合）、`search`（关键词全文检索）、`doctor`（健康体检）。每条命令全量重扫、纯内存构建索引，人读文本输出，全局 `--json` 供脚本消费。

## User Stories

1. 作为知识库维护者，我想列出某个页面的全部正向链接（含目标路径与原文写法），以便检查这页笔记的引用是否指向了正确的地方。
2. 作为知识库维护者，我想查询某页面的反向引用（列出引用方路径与行号），以便快速定位"谁在引用我"并顺藤摸瓜。
3. 作为知识库维护者，我想在 `links` 输出中直接看到未解析的死链，以便知道这页笔记里哪些链接写错了名字。
4. 作为知识库维护者，我想看全库标签聚合（按页面数降序），以便掌握知识库的主题分布。
5. 作为知识库维护者，我想输入一个标签名拿到所有打此标签的页面，父标签查询含全部子孙标签（`tags concepts` 同时命中 `#concepts/gc`），以便按主题导航。
6. 作为知识库维护者，我想用多个关键词做 AND 检索，以便在大量笔记中收窄到同时提及若干概念的页面。
7. 作为知识库维护者，我想让检索结果按"标题命中优先、内容频次次之"排序并附命中行摘录（每页至多 3 行、含行号），以便第一眼看到最相关的页面并直击上下文。
8. 作为知识库维护者，我想运行 `doctor` 一次性拿到三类发现——死链、孤岛页面、歧义链接，以便系统性地修复知识库结构。
9. 作为把质量关进流程的人，我想让 `doctor` 通过退出码（0 健康 / 1 有发现 / 2 用法错误）报告结果，以便把它挂进 pre-commit 或脚本。
10. 作为脚本作者，我想给任何命令加 `--json` 得到单个稳定字段的 JSON 文档，以便程序化消费而不解析人读文本。
11. 作为在笔记目录里工作的人，我想直接敲 `wiki-cli <命令>` 就分析当前目录，偶尔用 `--vault PATH` 分析别的库，以便零配置使用。
12. 作为用 Obsidian 记笔记的人，我的 `[[页面名|别名]]`、`[[子目录/页面名]]`、`[[页面名#小节]]` 写法应被正确解析（剥离别名与锚点、按页面名解析），以便工具兼容我的既有习惯。
13. 作为页面命名随意的人，我希望链接解析在精确匹配失败时按大小写不敏感兜底，以便 `[[python]]` 能连到 `Python.md`。
14. 作为在笔记里贴代码示例的人，围栏代码块与行内代码中的 `[[链接]]` 和 `#标签` 不应被统计，以便教学示例不污染真实引用关系。
15. 作为在 frontmatter 里管理元数据的人，`title:` 不参与链接解析、`tags:` 列表并入标签聚合，以便元数据与正文标签一体统计。
16. 作为中文笔记作者，CJK 页面名、CJK 标签、CJK 紧邻 `#` 的标签（`看看#python`）应是一等公民，而 URL 中的 `#`（`https://x#/a`）与纯数字标签 `#1` 不应误报，以便中文笔记不被误读。
17. 作为用自链接做导航的人，`[[自己]]` 在 `links` 中如实显示，但不构成反向引用、不把页面救出孤岛，以便孤岛判定诚实。
18. 作为使用页内标题锚的人，`[[#小节]]` 应被完全忽略不产生任何链接噪音，以便体检报告干净。
19. 作为知识库有重名页面的人，`[[notes]]` 指向 `a/notes.md` 与 `b/notes.md` 时应被判为歧义链接：反向引用记入每个候选页面，且 `doctor` 单独提醒我加路径消歧，以便既不丢信息又知道要修。
20. 作为笔记里有编码瑕疵的人，非 UTF-8 文件按容错方式读取不崩溃，以便一次坏文件不毁掉整次分析。
21. 作为手滑的人，路径不存在、缺参数、空搜索词应得到清晰的用法提示与退出码 2，以便快速自查。

## Implementation Decisions

- **Seam 划分（六模块）**：`scan`（vault → 页面文件流）→ `parse`（文本 → 页面结构）→ `resolve`（链接目标 × 页面全集 → 三态）→ `index`（页面集合 → 纯内存索引）→ `render`（查询结果 → 人读文本 | JSON）→ `cli`（argparse 接线 + 退出码，薄层）。依赖单向，前者不知后者。
- **存储（ADR-0001，硬边界）**：索引纯内存、每命令全量重建、无状态。缓存若未来出现只允许单文件 `.wiki_index.json` 形态；严禁 SQLite/向量库/外部检索服务。工具对 vault 只读，无任何写笔记路径。
- **页面身份**：页面 = vault 内 `.md` 文件，页面名 = 文件名 stem。链接解析顺序：含路径则按相对路径精确匹配；否则 stem 精确匹配 → 大小写不敏感兜底。H1/frontmatter title 不参与链接解析。
- **链接三态（resolve）**：Resolved / Dead / Ambiguous。Ambiguous = stem 匹配多个页面；其反向引用记入每个候选页面，`links` 中标注未唯一解析，`doctor` 单列。`[[页面#小节]]` 与 `[[页面#小节|别名]]` 剥离锚点与别名后解析。
- **自链接与页内锚**：`[[自己]]` 算正向链接、不构成反向引用、不影响孤岛判定；`[[#小节]]`（无页面部分）整体跳过、完全不计数。
- **标签提取**：仅正文（frontmatter `tags:` 另路并入）；围栏代码块与行内代码内一律豁免；`#` 后紧跟非空白非 `#` 才是标签（标题行、`##tag` 天然排除）；`#` 前为 ASCII 字母数字不算（URL 免疫）、CJK 紧邻可算；字符集 `[A-Za-z0-9_\-/` + CJK；纯数字无效（至少含一个字母或 CJK）；嵌套 `a/b` 按完整路径聚合、父查询含子孙。
- **frontmatter 最小解析**：手写解析器只认 `title:` 与 `tags:`（含单行列表两种写法），不引 PyYAML；解析失败按无 frontmatter 处理。
- **search 语义**：多关键词 AND；大小写不敏感子串匹配（无分词）；标题命中 = 页面名/H1/title 任一包含；排序：标题命中 > 内容出现频次 > 路径字典序；每页展示至多 3 条命中行（行号 + 截断行文本）。
- **doctor 语义**：死链 = Dead 链接（按出现处列出）；孤岛 = 反向引用为零的页面（按路径列出）；歧义 = Ambiguous 链接（列出链接处与全部候选）；头部统计行（页面数 · 链接数 · 标签数）；退出码 0/1/2。
- **vault 定位与扫描边界**：默认 CWD，`--vault PATH` 覆盖；递归扫描 `*.md`；跳过隐藏目录（`.` 开头）、符号链接、`.wiki_index.json`；非 UTF-8 文件容错读取。
- **CLI 形态**：纯标准库 argparse；五个子命令 `links <page>`、`backlinks <page>`、`tags [tag]`、`search <kw...>`、`doctor`；全局 `--vault` 与 `--json`；打包为标准 Python 包 + pyproject entry point `wiki-cli`；Python `>=3.10`。
- **render 契约（人读输出格式，访谈定稿）**：
  - `links`：`路径 (页面名)` 头行，每条出链一行 `→ 目标路径  [[原文]]`，死链行 `✗ 未解析: [[原文]]`
  - `backlinks`：`路径 (页面名) ← N 条反向引用` 头行，每条 `引用方路径:行号  [[原文]]`
  - `tags`：`#标签名  N 页` 逐行，页数降序、同数按字典序；`tags <tag>` 输出页面路径列表
  - `search`：`N 个页面命中 · 关键词: …` 头行，每页 `序号. 路径  标题命中/内容 ×频次` + 命中行缩进块
  - `doctor`：`体检: N 页面 · M 条链接 · K 个标签` + `✗ 死链` 块 + `⚠ 孤岛页面` 块 + `歧义链接` 块
  - `--json`：每命令输出单个 JSON 对象，字段名稳定；doctor 含 `dead_links`/`orphans`/`ambiguous` 数组

## Testing Decisions

- **唯一测试 seam：CLI 命令面**。所有测试通过调用 CLI 入口执行命令，断言 stdout（人读格式或解析后的 `--json`）与退出码。不直接测内部函数——内部行为全部由外部可观测行为承载。
- **固件 vault 即活规范**：每个边角规则对应一个最小固件目录（同名歧义、自链接、`[[#小节]]`、代码块示例、frontmatter 标签、CJK 页面名与紧邻标签、URL `#`、纯数字标签、嵌套标签父子查询、大小写兜底、非 UTF-8 文件、隐藏目录排除、多关键词 AND、无命中、空参数）。固件树同时覆盖五命令的正反例。
- **框架**：pytest（本机 3.12.8，下限 3.10），测试内以编程方式调用入口并捕获输出。
- **Prior art**：无（绿地项目）；本 spec 即首个测试纪律样板。

## Out of Scope

- `pages` 列表命令（Q13 选 b：严格保持需求五个子命令，不为便利性扩表面积；解析调试价值由测试覆盖）
- 任何写入笔记的路径（create/edit）——只读硬边界
- H1 标题参与链接解析
- 正则/模糊/拼音搜索、相关性算法
- 数据库/向量库/外部检索服务（ADR-0001）
- v1 缓存文件（`.wiki_index.json` 为唯一允许的缓存形态，万级页面卡顿时才触发）
- doctor 豁免入口页（真实痛感出现再加 `--entry`）
- 完整 YAML frontmatter 解析（仅最小 `title:`/`tags:`）
