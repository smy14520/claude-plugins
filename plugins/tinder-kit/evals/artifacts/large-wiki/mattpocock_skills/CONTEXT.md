# wiki-cli

一个纯本地的 Markdown 个人 Wiki 分析内核：扫描 `.md` 文件，回答关于链接、标签、内容的问题，并对知识库做体检。

## Language

### 结构

**Vault（知识库）**:
用户的 Markdown 笔记根目录，本工具唯一的输入。
_Avoid_: 仓库、workspace、项目

**Kernel（内核）**:
只读的分析核心：观察 Vault 并产出查询结果与体检报告，永不改写 Vault 内的任何文件。
_Avoid_: 守护进程、服务

**Index（索引）**:
由 Vault 派生出的、可随时丢弃重建的缓存。文件系统永远是唯一真相，索引损坏或过期的正确处理方式永远是重建，而非修复。
_Avoid_: 数据库、存储层

### 链接

**Wikilink**:
`[[页面]]` 双链语法，Kernel 唯一识别的内部链接形式。
_Avoid_: MD link、markdown link

**嵌入（Embed）**:
`![[页面]]`，视为一条指向该页面的普通链接。

**别名（Alias）**:
`[[页面|显示文字]]` 竖线后的显示文字，不参与页面身份，仅用于展示。

**锚点（Anchor）**:
`[[页面#小节]]` 中 `#` 之后的部分；匹配前剥离，不参与页面身份，原样存入索引备查。

**外部链接（External Link）**:
带 URI scheme（如 `https://`）的 wikilink 目标，排除在链接图与死链体检之外。

**已知局限**:
`[文字](x.md)` 形式的普通 Markdown 链接不解析——不计入反向引用，不参与死链体检。此为 v1 明确接受的取舍，非缺陷。

### 页面与匹配

**页面（Page）**:
Vault 内一个 `.md` 文件，身份 = 文件名去掉末尾 `.md` 后缀，全 Vault 唯一；重名是缺陷，由体检暴露。
_Avoid_: 文档、笔记文件

**匹配（Match）**:
链接目标与页面身份之间的字节级精确比较，唯一宽容是剥离目标末尾的 `.md` 后缀。大小写、空白、连字符一律不做归一化。
_Avoid_: 模糊匹配、fuzzy matching

**死链（Dead Link）**:
按匹配规则解析不到任何页面的 wikilink 目标。属于体检报告的缺陷类别，不是解析错误。

### 元数据与标签

**Frontmatter**:
文件第 1 行以 `---` 开始、成对闭合的元数据块，从正文与全文检索范围中剥离；不闭合时整体按正文处理，由体检暴露。Kernel 只提取其中的 `tags:` 键（行内列表与逐行列表两种形式），其余键一律忽略。
_Avoid_: YAML 头、metadata

**标签（Tag）**:
页面的分类单元，来源有二：frontmatter 的 `tags:` 与正文的 `#tag`，合并去重后参与聚合。`#` 须出现在行首、空白或非字母数字之后（故 `C#`、URL 锚点不算）；标签名不得以数字开头，`/` 是名字的普通字符，不展开层级；代码围栏与行内代码内不算标签。
_Avoid_: 分类、category、topic

### 检索

**全文检索（Search）**:
对页面身份与正文（frontmatter 剥离后）做子串 AND 匹配的查询；Latin 侧大小写不敏感，无相关性排序。
_Avoid_: 搜索引擎、智能搜索

### 体检

**体检（Audit）**:
对 Vault 的只读诊断。缺陷类别恰为四种：死链、孤岛页、重名页、畸形 Frontmatter。空页面、无标签页、未验证的锚点都不是缺陷。
_Avoid_: 健康检查、lint

**孤岛页（Orphan Page）**:
零入链的页面。首页、MOC 等入口页天然零入链，会被如实报告；Kernel 不设白名单或排除机制。
_Avoid_: 死页、孤立节点

### 约束（已确认的边界）

- Kernel 严格只读。`new` / `rename`（含反向链接改写）/ `delete` 等写操作是 v2 非目标。
- 不引入任何数据库（含 SQLite）；索引是单文件缓存。
