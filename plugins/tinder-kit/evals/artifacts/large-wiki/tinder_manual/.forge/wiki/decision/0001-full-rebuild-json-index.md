# 全量重建的单文件 JSON 索引，拒绝任何数据库

wiki-cli 需要为反向引用、标签聚合与全文检索提供查询数据，而需求明确拒绝重型数据库。我们拍定：每条命令都对知识库做一次全量重建得到索引，并持久化为知识库根目录下的**单个 `.wiki_index.json` 文件**（不做 `.wiki/` 目录拆分）—— 文件系统是唯一真实源，索引永远是可丢弃的派生物，任何数据库（包括 SQLite）一律不引入。选它是因为正确性免费获得、零依赖安装、产物人类可读且可被外部工具直接消费。

## Considered Options

- **SQLite / 任何嵌入式数据库** —— 否决：违背"拒绝重型数据库"的需求底线，引入运维与依赖负担。
- **持久索引 + mtime 增量更新** —— 否决：引入缓存失效的正确性负担，个人规模下性能收益趋零。
- **纯内存索引不落盘** —— 否决：丢失"极简 JSON 索引"作为外部消费接口的价值。

## Consequences

接受每次命令 O(N) 全量扫描的代价（个人规模数千页为毫秒级）；索引 schema 演进无需迁移逻辑（整体重建即可）；不存在跨命令的缓存失效问题 —— 每条命令都从头重建，持久化文件仅是最近一次重建的快照。

## Revisit When

知识库规模超过 1 万页面，或单命令端到端延迟明显超过 1 秒时，重新评估增量更新策略。
