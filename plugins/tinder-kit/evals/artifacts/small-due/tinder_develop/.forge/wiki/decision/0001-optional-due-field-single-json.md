# 单 JSON 文件中的可选 due 字段（缺省键即无截止日期）

Todo CLI 的数据已存放于单一 `.todos.json`（`{"todos": [...]}`）。为支持截止日期，拍板：任务对象新增**可选**字段 `due`，值为严格 `"YYYY-MM-DD"` 字符串；没有截止日期的任务**完全不写该键**（而非写 `null`），读取方一律宽容处理缺失键。旧版本工具读新文件会忽略多余键，新版本读旧文件得到"无截止日期"，双向向后兼容，无需 schema 版本号与迁移脚本。

## Considered Options

- `null` 表示无截止日期 — 否决：与既有 `t.get("done", False)` 的宽容缺省风格不一致，且让文件充斥无信息量的键；
- 引入 `version` 字段 + 迁移脚本 — 否决：单文件单用户场景下，为可选字段做版本化属于过度设计；
- 独立存储文件（如 `.todos.due.json`）— 否决：拆散任务与其截止日期，且需求明确要求数据留在现有单文件中。

## Consequences

- 用户文件一旦在真实世界流通，"缺省键 = 无截止日期"即成为对外承诺；此后改名或改语义需要真实数据迁移，成本高昂；
- 读取方必须始终以宽容缺省方式访问 `due`（如 `t.get("due")`），绝不允许裸下标访问，否则旧文件会直接抛 KeyError。

## Revisit When

- 出现时刻级（时分秒）提醒需求，`due` 需升级为 datetime；
- 出现多设备同步或多用户需求，单 JSON 文件不再够用。
