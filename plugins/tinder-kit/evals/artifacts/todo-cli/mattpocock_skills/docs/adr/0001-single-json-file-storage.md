# 0001 - 存储使用单一本地 JSON 文件，拒绝数据库

个人自用、单机单用户的待办工具。我们决定所有任务持久化在一个本地 JSON 文件中（默认 `~/.todos.json`），明确拒绝 SQLite 或任何数据库。理由：单用户场景下数据库提供的并发控制、查询优化和迁移工具毫无用武之地，而 JSON 文件零依赖、可直接用编辑器和 `cat` 检视、整个程序不需要任何第三方存储组件。代价是每次写命令都整文件重写、无并发安全——在个人规模下这些代价不存在。

## Considered Options

- **SQLite**：被拒绝。引入驱动依赖和 schema 概念，换来的能力（并发、索引）在本场景没有需求。
- **todo.txt 纯文本行格式**：被拒绝。追加式文本行难以承载"永不复用的 ID 计数器"这类文件级状态，解析也更容易碎。

## Consequences

- 每条写命令 = 读全文件 → 修改 → 原子重写全文件。
- 文件即数据，无 schema 版本迁移机制；格式演进靠人肉改。
- 明确不做：跨机同步、Web/GUI（见范围边界）。
