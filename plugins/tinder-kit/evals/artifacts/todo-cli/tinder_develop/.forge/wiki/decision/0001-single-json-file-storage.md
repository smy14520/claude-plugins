# 单一 JSON 文件存储（.todos.json）

本工具是本地单用户 CLI，数据量为个人清单量级，且项目目标是零第三方依赖、透明可审计（人能直接打开文件查看、手改救急）。因此拍定：全部 Todo 持久化为当前目录下的单一 JSON 文件 `.todos.json`，整体读、整体写；`TODO_FILE` 环境变量仅覆盖该文件路径（测试隔离与多清单），绝不产生第二个数据文件。

## Considered Options

- **SQLite** — 为并发写与大数据量买保险，此场景用不上；二进制格式不可直接人读，违背透明可审计目标。否决。
- **CSV** — 嵌套结构（一个 Todo 挂多个 Tag）表达别扭，转义规则易错。否决。
- **多文件 / 每 Todo 一文件** — 违背用户拍板的"单一文件"原则，id 唯一性维护复杂化。否决。

## Consequences

- 写入采用 tmp 文件 + 原子替换，避免半写状态损坏数据；
- 无并发写保护——单用户本地场景接受此代价；
- 若未来迁移数据库，需一次性转换脚本。

## Revisit When

- 单文件条目数达到万级导致加载可感知变慢；
- 出现多设备同步或多人共用清单的真实需求；
- 需要并发写入。
