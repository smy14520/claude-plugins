# 04 — 公司 IM 开放 API 调研

Type: research
Status: resolved
Blocked by: None

## Question

公司具体用哪家 IM 尚未确认（人类需向 IT/同事确认，此项记入 Answer 的 checklist）。请对三家候选的开放平台能力做对比调研：

- **企业微信 / 钉钉 / 飞书**各自的：消息推送（群机器人 webhook / 应用消息）、OAuth 网页登录、任务/日历类开放 API
- 各家的自建应用准入门槛（是否需要企业管理员审批、个人能否先行试用）

产出：一张三家能力对比表 + 对「到期提醒」与「远期 IM 集成」两个下游决策的建议。

## Answer

查证于 2026-09-26；完整证据（官方文档 URL、原文摘录、存疑项）在调研工作区 `.forge/research/im-openapi/`（index.md 为入口），长期认知已晋升至 `.forge/wiki/research/im-openapi.md`。

### 三家能力对比

| 维度 | 企业微信 | 钉钉 | 飞书 |
|---|---|---|---|
| **群机器人 webhook** | 有（`cgi-bin/webhook/send?key=...`） | 有（群设置→智能群助手→自定义） | 有（`/bot/v2/hook/...`） |
| **机器人准入** | 群内自行添加；文档未提需管理员审批 | 群内自行添加，无需管理员审批 | 官方明文「无需租户管理员审核」 |
| **机器人限流** | 20 条/分钟 | 20 条/分钟（超限 1302，当分钟丢弃） | 100 次/分钟、5 次/秒 |
| **机器人安全机制** | 仅靠 webhook key 保密 | 强制三选一：关键词(≤10)/加签(HmacSHA256)/IP 白名单 | 可组合：关键词/IP 白名单/签名校验 |
| **应用消息推送** | 有：`message/send`（agentid + touser/toparty/totag） | 有：工作通知 `asyncsend_v2`（agent_id + userid_list） | 有：`im/v1/messages`（tenant/user token，im:message） |
| **自建应用准入** | 需企业注册 + 管理后台建应用；未验证企业 100~200 人、API 权限可能收紧（存疑） | 需开发者权限（管理员授予）；非管理员建的应用发布需主管理员审批 | 创建门槛低，但权限生效/可用范围需企业管理员审核发布 |
| **个人先行试用** | 个人可免执照注册企业，但规模/API 受限 | 自建组织当主管理员，全流程自批 | 自建租户当管理员，全流程自批；有免费版 |
| **OAuth 网页登录** | 有，双轨：客户端内网页授权 + Web 扫码登录（wwlogin），需自建应用 + 回调域 | 有，新版统一 OAuth2.0 授权码（`login.dingtalk.com/oauth2/auth`），旧版扫码登录下线中 | 有，`authen/v1/authorize` → oidc access_token，支持第三方网站扫码登录 |
| **任务/待办 API** | 无任务创建 API（仅待办详情/状态类，弱证据）；实践用消息卡片/智能表格替代 | 有：待办 API（`/v1.0/todo/users/{unionId}/tasks`） | 有：任务 v2（`/task/v2/tasks`，执行人/截止日/重复规则） |
| **日历 API** | 有，完整族：日历 + 日程 CRUD、参与者、回调通知 | 有：日程、参与者（单次≤500人）、忙闲、会议室 | 有：calendar v4，日程 CRUD、参与者、会议室、忙闲（1000 次/分钟） |

注：群机器人三家都是**单向**推送（飞书官方明文不能响应用户消息）；双向交互必须走自建应用 + 事件回调，即进入管理员审批区。

### 建议

**对 ticket 06（到期提醒通道与时机）**：
- 首选通道用「IM 群机器人 webhook」：三家都零审批、当天可接通，提醒量级（digest + 单发 + 逾期升级）远低于 20 条/分钟红线，单机定时任务直接 POST JSON 即可，符合「不引入消息队列」约束。
- 因公司用哪家未确认，工程上建议做成 webhook provider 抽象（配置 URL + 三家适配器，差异只在安全机制：钉钉强制加签、飞书可选签名、企微仅 key 保密）。
- 兜底通道：站内 digest 必做（MVP 不依赖任何外部 IM）；邮件可作次选。IM 通道定位为「锦上添花的增强」，不是 MVP 阻塞项。

**对远期 IM 集成（map「Not yet specified」中的产品形态悬案）**：
- 若产品形态是「通知机器人」：零门槛 webhook 已覆盖，MVP 后低成本接入。
- 若要做「命令式交互」（在 IM 里查任务/改状态）：必须自建应用（三家都要管理员审批），且飞书/钉钉的任务与日历 API 是一等公民、企微没有任务 API——若最终产品形态倾向深度双向集成，飞书 ≈ 钉钉的 API 丰度是加分项，企微会受限。
- OAuth 网页登录三家都有且形态趋同（授权码 + 扫码），不构成选型决定因素；唯一 gotcha：飞书 user_access_token 365 天强制重授权，登录态需处理。

### 人类 checklist（需向公司 IT/同事确认）

- [ ] 公司标准 IM 到底是哪家（企微 / 钉钉 / 飞书）？是否有多个并存？
- [ ] 能否找到该 IM 的企业管理员？自建应用（若需要）是否可获批？公司对自建应用接入有无政策限制？
- [ ] 群机器人 webhook 是否被 IT 策略允许/已在用（有的团队已有现成机器人）？
- [ ] （仅当答案是企微时）企业是否已验证/认证？未验证企业的 API 权限是否受限需实测。
