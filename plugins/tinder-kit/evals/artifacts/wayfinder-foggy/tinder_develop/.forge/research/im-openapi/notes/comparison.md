# Notes — 三家 IM 开放平台能力对比

依据：`../raw/wecom.md`、`../raw/dingtalk.md`、`../raw/feishu.md`（查证于 2026-09-26）。仅陈述已核实的外部事实与注明依据，不做最终选型拍板（公司实际用哪家 IM 是人类待决项）。

## 一、能力对比表

| 维度 | 企业微信 | 钉钉 | 飞书 |
|---|---|---|---|
| **群机器人 webhook** | 有（`qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...`） | 有（群设置→智能群助手→自定义机器人） | 有（`open.feishu.cn/open-apis/bot/v2/hook/...`） |
| **机器人准入门槛** | 群内自行添加；官方文档未提及需管理员审批 | 群内自行添加，无需企业管理员审批 | 官方明文「无需租户管理员审核」 |
| **机器人频率限制** | 20 条/分钟 | 20 条/分钟（超限错误码 1302） | 100 次/分钟、5 次/秒（单租户单机器人） |
| **机器人安全机制** | 保管好 webhook key；文本长度限制 | 至少其一：关键词(≤10)/加签(HmacSHA256)/IP 白名单 | 可组合：关键词(≤10)/IP 白名单(≤10)/签名校验 |
| **机器人消息类型** | text/markdown/image/news/file/voice/模板卡片等 8 种 | text/link/markdown/action_card 等 | text/post/share_chat/image/interactive 卡片（卡片不支持回调交互） |
| **应用消息推送** | `message/send`（agentid + touser/toparty/totag） | 工作通知 `asyncsend_v2`（agent_id + userid_list） | `im/v1/messages`（tenant/user_access_token，im:message 权限） |
| **应用准入门槛** | 需企业注册；已有组织内需管理员创建/授权；未验证企业 100~200 人且 API 权限可能收紧（待确认） | 需开发者权限（管理员授予）；非管理员建的应用发布需主管理员审批 | 创建门槛低，但权限生效/可用范围需**企业管理员审核发布** |
| **个人/小团队先行试用** | 个人可免执照注册企业（未验证），但规模与 API 受限 | 自建组织当主管理员可全流程自批 | 自建租户当管理员可全流程自批；有免费版 |
| **OAuth 网页登录** | 有，双轨：客户端内「网页授权」(oauth2/authorize) + 「企业微信Web登录」扫码(wwlogin)；需自建应用+回调域 | 有，新版统一 OAuth2.0 授权码模式（`login.dingtalk.com/oauth2/auth` → `oauth2/userAccessToken`）；旧版扫码登录下线中 | 有，`authen/v1/authorize` → `authen/v1/oidc/access_token`；支持网页应用授权与第三方网站扫码登录 |
| **任务/待办 API** | 无完整任务管理 API（仅见待办详情/状态类接口，弱证据）；实践用消息卡片/智能表格替代 | 有：待办 API（`/v1.0/todo/users/{unionId}/tasks`，Todo.Task.Write） | 有：任务 v2 API（`/task/v2/tasks`，task:task，支持执行人/截止日/重复规则） |
| **日历 API** | 有，完整族：日历 CRUD + 日程 CRUD + 参与者 + 回调通知 | 有：日程/日历、参与者（单次≤500人）、忙闲查询、会议室 | 有，calendar v4：日程 CRUD + 参与者 + 会议室 + 忙闲（1000 次/分钟） |

## 二、关键差异与工程含义

1. **提醒推送零门槛通道三家都有**：群机器人 webhook 均无需企业级审批，小团队当天可接通；到期提醒（digest + 单发 + 逾期升级）的量级远低于 20 条/分钟红线，限流不构成约束。三方差异只在安全机制（钉钉强制三选一、飞书可选签名、企微仅靠 key 保密）。
2. **群机器人都是单向的**：飞书明文「不能响应用户消息」，钉钉/企微同类。要做命令式双向交互（在 IM 里改任务状态），必须走自建应用 + 事件回调，那就进入「企业管理员审批」区。
3. **自建应用的审批是三家共同的真实门槛**：在「公司已有组织」里，任何应用级集成都要找管理员；差别仅在流程顺滑度（飞书需发版审核、钉钉需开发者权限+发布审批、企微需管理后台建应用）。个人先用自己注册的组织/租户试通全链路是三家通行的试用路径，但企微未验证企业有规模与 API 收紧风险（存疑项）。
4. **远期深度集成的 API 丰度：飞书 ≈ 钉钉 > 企微**：任务/待办与日历 API 飞书、钉钉都是一等公民；企微日历完整但没有任务创建 API。
5. **OAuth 三家都有**，形态趋同（授权码模式 + 扫码登录），差异在端点与 scope 细节；飞书有 user_access_token 365 天强制重授权的 gotcha，钉钉 redirect_uri 必须严格匹配。
