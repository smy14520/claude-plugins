# Wiki — 全局分层记忆与知识管家

项目知识、架构规则与排坑经验的统一管理中枢。消除“知识孤岛与记忆污染”，运用**三问决策罗盘**将事实精准分流至三级记忆体系。

## 三级记忆体系拓扑（Three-Tier Memory）

```
┌──────────────────────────────────────────────┐
│ L1: 宪政层 (CLAUDE.md)                        │  <-- 全局 100% 常驻，最高底线与核心禁令
├──────────────────────────────────────────────┤
│ L2: 法规层 (.claude/rules/<domain>.md)       │  <-- 领域/文件按需挂载，防天然冲动的硬准则
├──────────────────────────────────────────────┤
│ L3: 百科层 (.forge/wiki/<type>/<slug>.md)    │  <-- 零默认成本，轻地图按需检索的长尾知识与深水暗坑
└──────────────────────────────────────────────┘
```

---

## 知识归宿三问罗盘（The 3-Question Placement Compass）

当捕获到一条事实、决策、排障教训或契约时，依次执行三问裁决：

```
                    [ 捕获到一条事实 / 决策 / 踩坑 / 约束 ]
                                       │
                 (问 1: 它是否是全项目 100% 任务都要遵守的最高底线？)
                                  ┌────┴────┐
                                 YES        NO
                                  │         │
                           ┌──────┴─────┐   ▼
                           │ CLAUDE.md  │ (问 2: 模型是否极容易产生天然冲动去犯错？
                           └────────────┘  且它是一句硬性的行动规范？)
                                            ┌────┴────┐
                                           YES        NO
                                            │         │
                                     ┌──────┴─────┐   ▼
                                     │   rules/   │ (问 3: 它是否是长尾、低频、但涉及
                                     └────────────┘  多文件联动、深层原理或平台 Bug 的知识？)
                                                      ┌────┴────┐
                                                     YES        NO (代码自证的废话直接丢弃)
                                                      │
                                               ┌──────┴─────┐
                                               │   wiki/    │
                                               └────────────┘
```

### 1. 问范围（Scope）── 是否进 L1 `CLAUDE.md`？
- **判据**：是否是全项目无论任何模块、任何任务都必须遵守的最高准则（如技术栈选型、包管理器铁律、提交归属权）；
- **正例**：“本项目机制在插件，标准在项目”、“提交权属于用户，AI 严禁自动 commit”；
- **反例**：某个特定图表库的配置写法（严禁写入 `CLAUDE.md`）。

### 2. 问诱惑与语态（Temptation & Imperative）── 是否进 L2 `.claude/rules/`？
- **判据**：强模型是否具有**极高频的默认倾向去犯错**？且能否抽象为一句简短有力的正向硬准则？
- **正例**：“严禁引入 ORM，所有数据库查询走原生 SQL”、“严禁在循环内发起单独网络请求，必须批量合并”；
- **反例**：“为什么当年选手写 SQL 的详细 Benchmark 报告”（报告进 L3 Wiki，结论进 L2 Rules）。

### 3. 问长尾与信噪比（Signal-to-Noise）── 是否进 L3 `.forge/wiki/`？
- **判据**：是否是长尾、平时不碰该模块时知道无用、但碰到了就要命的隐性事实？
- **分类收录于 `.forge/wiki/`**：
  - `gotcha/`：反直觉的平台 Bug、依赖库未公开怪癖、版本兼容性暗坑；
  - `cross_cut/`：“改动接口 A 必须联动修改 B、C、D 另外 3 处”的多文件修改链路；
  - `decision/`：重大架构决策推导与被否决备选路径的实证代价；
  - `concept/`：复杂业务领域核心实体定义与边界。

## 准入纪律：三收三不收

| 严禁入库（三不收 ❌） | 必须收录（三收录 ✓） |
| :--- | :--- |
| **代码自证的事实**：函数入参、返回值类型、单纯的 API 清单（让代码自己回答）。 | **反直觉的暗坑（Gotcha）**：依赖库的未公开 Bug、平台兼容性陷阱、特殊环境配置。 |
| **单文件局部细节**：仅影响单个函数内部实现的临时变量。 | **跨文件修改链路（Cross-cut）**：修改某个核心接口，必须联动修改另外多处的协同路径。 |
| **未经验证的猜想**：没有命令、测试或真实报错支撑的口头推论。 | **被否决的技术路径（Rejected Paths）**：尝试过但被证实走不通的方案及其实证代价。 |

## 权限与分级审批（Guardrails）

- **L1 (`CLAUDE.md`) & L2 (`.claude/rules/`) 变更**：
  - **严禁静默修改**！
  - 必须在终端向人类展示精准的 Git-style Diff 提议，获得明确同意后方可使用 `Edit` 工具写入。
- **L3 (`.forge/wiki/`) 变更**：
  - 采用**顺风车提案（Rider Proposal）**：在 `/fix` 或 `/develop` 收尾时，顺带附带一条极简入库建议，人类回车即收录。
- **涟漪更新原则**：
  - 当新发现推翻了老文档，**严禁静默擦除历史内容**；
  - 必须采用追加演进节（如 `## 2026-09 演进更新`），保留历史背景与演化依据。

## 符号锚与代码防漂移（Drift-Proof Anchors）

- 引用代码一律使用**符号锚（`file#symbol`）**，严禁使用脆弱的行号：
  - 正确：`[[src/auth/jwt.ts#refreshToken]]`
  - 错误：`src/auth/jwt.ts:45`（代码增删一行即全部失效）
- **体检（Linting）**：
  - 检查符号锚所指向的文件与导出符号是否存在，符号失效或重命名时立即报警。

---

## 地图索引与按需检索（Map-Reduce）

- **轻量地图（`.forge/wiki/index.md`）**：
  - 仅维护页面路径、一句话触发场景（`description`）与标签（`tags`）；
  - 全局索引控制在极小 Token 预算内。
- **按需索骥**：
  - 开工或访谈时，先扫描轻量地图，仅根据本次任务涉及的标签与文件**单篇提取**相关页面，严禁将整个百科全量灌入上下文。

---

## 知识晋升机制（Knowledge Promotion）

当 `.forge/wiki/gotcha/` 中的某条暗坑在多个任务中被重复触碰、证实是模型频繁犯错的高频盲区时，主动提议将其晋升为 `.claude/rules/<domain>.md` 中的前置硬准则。
