# 架构知识内核

架构师审计的专业底座。每条按三段式使用：**意图**（它回答什么问题）、**代价**（它引入什么成本）、**反判据**（什么时候不该用它）。模式是词汇不是规定——引用名字是为了让取舍可讨论，不是为了套用；判定一个结构好不好，先过下面的判断基准，再谈模式。

## 判断基准（先于一切模式）

- **单一定义点**：每个实体、操作、状态只有一处权威定义。出现第二处即形态退化——重复的两份会各自漂移，测试往往只盖住其中一份。
- **依赖方向**：依赖指向稳定方，越稳定的越该是抽象（接口），越易变的越该是实现（SDP/SAP）。底层 import 高层、被依赖方知道所有调用方，都是方向腐化。
- **认知负荷边界**：一个模块要装得进一份工作记忆——对人是团队认知负荷（Team Topologies：一个团队最多管一个复杂域），对 agent 是一个干净 context window。装不下说明它是两个模块。
- **isolation 测试**：不看 internals 能否理解一个单元？改 internals 会不会破坏消费者？两个都过才是边界，否则边界没切对。
- **one-way door vs two-way door**：数据格式、对外契约、目录归属、状态语义是不可逆的贵决定，值得前置拍板；其余先走通，错了再改。
- **抽象时机**：第二个用例出现前不建抽象。抽象的正确性由"至少两个不同的真实消费者"证明，不是由"将来可能"证明。
- **change amplification**：一个好改动应该落在一处；同一个改动要动多处 = 放置错误或边界切错（对应 Fowler 的 Shotgun Surgery，但从源头防止而不是事后重构）。

## 架构风格与模式速查

- **深模块与薄接口**：厚逻辑藏在极小接口背后，调用方低认知负荷，实现具备极高重构自由度。
- **六边形 / 端口适配器**：业务领域居中，外部 IO 全走端口与适配器，降低未来替换供应商的摩擦。
- **状态单点**：一份可变状态只有一个权威写入者（Store/Actor），其它地方全为只读派生。
- **幂等是重试的前提**：外部网络脆弱，任何异步通知或重试必须设计明确的幂等键。
- **超时 + 重试退避 + 熔断**：三者配套出现，缺一不可。
