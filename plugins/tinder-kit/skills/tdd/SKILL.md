# TDD — 基于深接缝的红绿重构素养

将测试从“外部门禁（Gate）”还原为**“赋能大刀阔斧重构的安全护盾与改动背书”**。结合 `codebase-design` 的深模块理念，拒绝脆弱的微观浅单测，只在核心接缝上构建行为测试。

## 核心法则：只测深接缝（Test at the Seams）

1. **拒绝为私有函数/内部 Helper 堆砌单测**：
   - 内部辅助函数会随着重构频繁变动，为它们写测试会导致测试脆性极高，扼杀重构意愿；
2. **测试必须落在预定的深接缝（Seams）上**：
   - 测试只关心从 Seam 接口输入什么、在系统另一端产生了什么可观测行为/输出；
   - 只要 Seam 契约不破，内部实现推倒重写三次，测试一行都不需要动！

## 红-绿-重构循环（Red-Green-Refactor）

```
  ┌──────────────┐      ┌──────────────┐      ┌──────────────┐
  │ 1. RED       │ ───► │ 2. GREEN     │ ───► │ 3. REFACTOR  │
  │ 接缝处写断言 │      │ 最快跑通契约 │      │ 护盾下自由重 │
  │ 确认因缺而红 │      │ 确认测试全绿 │      │ 构内部深模块 │
  └──────────────┘      └──────────────┘      └──────┬───────┘
         ▲                                           │
         └───────────────────────────────────────────┘
```

1. **RED（先红）**：
   - 在约定的 Seam 上编写具体的行为测试用例（覆盖主路径、异常路径、边界与幂等性）；
   - 执行测试，**亲眼确认它变红，且变红的原因确实是因为“该功能尚未实现”**（而非语法错误或环境问题）。
2. **GREEN（变绿）**：
   - 编写必要的实现代码，跑通该 Seam 上的测试；
   - 只要能验证契约，此时允许最直接的代码实现。
3. **REFACTOR（在护盾保护下自由重构）**：
   - **这是强模型智能真正爆发的阶段**：在 Seam 测试全绿的背书下，放心大胆地应用 `codebase-design`：
     - 提炼内部算法、消除重复、加固错误处理、优化信息隐藏；
     - 每改一步重跑 Seam 测试，测试始终保持绿；
   - 这样产出的代码既有坚不可摧的正确性，又拥有极高的架构审美。
