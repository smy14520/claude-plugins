# Review — 双轴代码与契约审查

以独立的客观第三方视角审查工作树中的改动，将代码审计明确划分为互不污染的两个轴向：**代码规范与坏味道（Standards）** 与 **规格契约兑现度（Spec）**。

## 双轴审查模型

```
  ┌─────────────────────────────────┐       ┌─────────────────────────────────┐
  │   轴 1: Standards (代码与架构)   │       │   轴 2: Spec (需求与深接缝契约)   │
  ├─────────────────────────────────┤       ├─────────────────────────────────┤
  │ • 项目特定代码规范与架构原则     │       │ • 是否忠实兑现了 spec.md 中的    │
  │ • Fowler 12 味代码坏味道基线    │       │   2~3 个核心 Seams 行为约定？   │
  │ • 深模块设计：接口是否足够薄？   │       │ • 是否偷换概念、收窄边界？      │
  │ • 错误处理、边界防守、日志卫生   │       │ • 是否吞掉异常、假冒测试？      │
  └─────────────────────────────────┘       └─────────────────────────────────┘
```

## 执行流程

1. **确定审查基准线**：
   - 提取审查范围（`git diff` 或自任务起点 SHA 至今的累积改动）；
   - 读取任务的 `spec.md`（特别是 `Agreed Seams`）以及项目 `CONTEXT.md`。
2. **轴 1 审查：Standards 轴**：
   - 对照 Fowler 代码坏味道（重复代码、过长函数、依恋情结、基本类型偏执、发散式变化等）；
   - 检查是否有硬编码秘钥、未捕获的并发竞争、不必要的全局状态；
   - 琐碎的代码格式或小异味：能直接修就直接修，不浪费口舌。
3. **轴 2 审查：Spec 契约轴**：
   - 逐项核对 `spec.md` 中声明的每个 Seam 是否在真实代码中有清晰对应的实现位置；
   - 检查测试是否真实驱动了该 Seam，是否存在“测试全绿但核心断言全被注释/弱化”的作弊行为。
4. **全量防回归验证**：
   - 运行项目全量测试套件，确保没有破坏任何既有功能。
5. **产出背书结论**：
   - 汇总生成 `endorsement.md`（或更新 `state.json` 的 endorsement 字段）；
   - 若全部通过，盖上 `review_verdict: clean`；若有架构分歧，列出清单向人类汇报。
