# Handoff — 上下文压缩与状态交接

将当前会话中高噪音的执行细节过滤，提炼出一份具备无损续接能力的轻量交接文档，让全新的 Agent 或同事无需翻阅完整历史记录即可立即接手。

## 适用场景（何时使用）

严格遵循阶段边界（Phase Boundaries）原则，仅在出现物理边界跨越时调用本技能：

1. **开发者主动暂停或会话防爆**：会话接近智能衰减区（~150k tokens）、更换终端或下班暂停；
2. **交接给人类同事**：将当前排查到一半的现场打包给团队成员；
3. **切换执行工具（New Harness）**：跨客户端、跨模型或跨目录继续工作；
4. **原型探索双向桥接（Prototype Bridge）**：在访谈中遇到未决技术疑问时，导出上下文前往原型分支（`/prototype`），实验完成后再用 handoff 将经验结论带回主会话。

> **反模式警示**：在同一个未中断的会话内推进正常开发时，遵循 **Continue** 原则原地推进，**严禁机械地在每个阶段后生成无谓的交接垃圾文件**。

## 核心法则

1. **反重复原则（Anti-Duplication）**：
   - 绝不重复已被其他产物捕获的内容（代码、`spec.md`、ADRs、`state.json`、commits、diffs）；
   - 只能通过相对路径或引用指向它们。
2. **不可推导性准则（Non-Derivability Criterion）**：
   - 重点记录无法从代码直接看出的隐性决策、被证实的死胡同（试过但失败的方案及原因）以及外部环境暗坑；
   - 简单改动三两句交代清楚，复杂场景写透因果，拒绝死板字数限制。
3. **脱敏保护**：
   - 严格过滤并剔除 API keys、密码、凭据等敏感信息。

## 输出结构与规范

编写一份高密度的交接文档，包含以下要素：

1. **当前断点与现状（Current Status & Blockers）**：
   - 当前停留在哪个具体环节，达成了什么共识，面临什么未决卡点或试错结论；
2. **关联资产索引（Touchpoints & References）**：
   - 相关文件的相对路径，关联的 `spec.md`、ADR 或分支指针；
3. **建议下一步指令（Suggested Skills）**：
   - 明确写明接棒者启动时应调用的技能（如 `/develop <slug>`、`/implement`、`/code-review` 等）。

## 存储位置

- **任务上下文**：若处于 `.forge/tasks/<slug>/` 任务中，落盘至 `.forge/tasks/<slug>/handoff.md`（单文件原子覆盖，杜绝生成编号累积垃圾）；
- **通用上下文**：若非特定任务，保存至系统临时目录（如 `/tmp/handoff-<slug>.md`），不污染项目代码库。
