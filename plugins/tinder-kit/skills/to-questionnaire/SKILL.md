# To-Questionnaire — 反向审问与异步决策问卷

当开发者面临一个**自己缺乏背景、无法独自决定的分歧**（如产品定位、法务合规、业务权衡、跨部门依赖）时，将其转化为一份标准、高信噪比的 Markdown 决策问卷，供对方异步填写或在会议中逐项拍板。

## 核心哲学：Grill the send, not the subject

普通的 `grilling` 技能审问的是方案本身；但如果你自己根本不知道答案，继续逼问你只会导致幻觉和内耗。

**`to-questionnaire` 反转视角：只审问“发送（The Send）”**：
- 对方是谁？他们的专长是什么？
- 你需要从他们那里拿回什么具体结论？
- 问卷瞄准的正是**“对方知道的”与“你需要的”之间的信息鸿沟**。

---

## 三步执行步骤（Three Steps）

### 1. 审问接收人（Who is it going to?）
在一次简洁交互中，向开发者澄清：
- 接收人的具体角色、专业背景以及与开发者的协同关系；
- **目标**：锁定问卷的语言语态（业务语言 vs 技术语言）以及需要补充的上下文厚度。

### 2. 审问待决缺口（What do you need back?）
在一次简洁交互中，向开发者锁定：
- 开发者无法独自裁决的具体事实、业务分支或拍板要求；
- **Completion criterion**：形成一份明确的清单——开发者拿到哪些答案后便能无阻碍继续开工。

### 3. 起草并落盘问卷（Draft & Save）
针对上述缺口生成结构严谨的问卷，直接写入 `.forge/questionnaires/<slug>.md`（若未显式指定 slug，从议题推导极简短名）：
- 每个问题只问一个概念；
- 重要或易被草率回答的问题下方附带一行 `_Why this matters: ..._`；
- 每个问题下方附带标准引用格式的留白回答框（`> `），便于对方直接在 Markdown 中打字回复；
- **在终端显式输出文件路径与摘要预览**，提示用户可直接复制发送至 IM、邮件或协作文档。

---

## 标准问卷结构模板（Document Structure）

落盘在 `.forge/questionnaires/<slug>.md` 的文档必须遵循以下结构：

```markdown
# 决策问卷: {议题标题}

**目标 (Purpose):** 为什么需要这份问卷，以及悬而未决的决策将对开发造成什么影响。
**发起人 (From):** {开发者角色} | **填答人 (To):** {决策人角色}
**结论用途:** 收回答案后将直接折入系统设计与 Seams 行为契约。

## 1. 背景摘要 (Context)

用 1~2 段精炼文字向接收人同步背景。背景写到对方足以判断为止。

## 2. 填答指引 (How to answer)

- 期望反馈时间与预估耗时（如：约需 5 分钟）；
- 允许局部回答或直接注明“不确定/需进一步商榷”，请勿跳过问题。

## 3. 核心决策项 (Questions)

<!-- 按业务主题分组，最重要的前置决策排在首位 -->

### Q1: [具体问题描述，一问只表达一个核心决策]

_Why this matters: 解释为什么必须由您裁决，以及不同选项对系统实现的影响_

> [请在此处填写结论或勾选倾向方案]

### Q2: [第二个具体问题]

_Why this matters: ..._

> 

## 4. 补充说明 (Anything else?)

除了上述问题之外，是否有任何我们尚未考虑到、但对本次改动至关重要的背景或风险？

> 
```
